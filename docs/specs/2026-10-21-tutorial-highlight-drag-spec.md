# チュートリアル改訂仕様 — 蛍光色の案内・成功メッセージ・Iパネルのドラッグ練習

作成日: 2026-10-21
対象: `KoiChem/AlkanePuzzle` の独立試作 `tutorial.html`
確認した実装: `abf87b29c7c933eb0dd722188352cca34732aaea`
状態: 実装引き継ぎ用。今回の依頼は仕様作成まで。

### 最新の修正方針: 必須ガイドを直接切り替える

ユーザーからSafari・Chromeの両方で動かない報告を受け、抑制設定時にアプリ自身が両方の案内を停止する条件を再現した。端末の実際の設定値は不明。推奨方針の実装・検証・公開は承認済み。

必須の点灯案内とボタン点滅は、一つのJavaScript時計でクラスと色を直接切り替える。OSの `prefers-reduced-motion` によって完全停止させない。紙吹雪などの装飾だけを抑制対象にする。スワイプの450ms刻み・累積保持・650msの全点灯保持・500msの消灯、ボタンの1秒点灯／1秒消灯は維持する。色は淡い `#FFF9B0` とし、枠と光も弱める。操作中・ページ非表示中は時計を止めて復帰時に再開するが、表示中の単なるblurでは案内を止め続けない。画面の再描画で時計をリセットしない。

検証では抑制設定オン／オフの両方で動くことを合格条件とし、従来の「抑制設定なら静止する」テストは置き換える。CSSアニメーションとWeb Animations APIを使えない状態でも、必須ガイドの色切替が動くことを確認する。この修正方針を以下の記述より優先する。

### 追加承認: レモン色と点灯を残すスワイプ案内

本仕様の初版は `87d0a9a` で公開済み。以後のユーザー指示により、強調色は緑みのないレモンイエロー `#FFF44F` とする。スワイプは「始」の丸印・文字を削除し、開始マスから450msごとに順に点灯させる。通過済みのマスは同じ黄色で点灯を維持し、全経路が光ってから650ms保持、500ms消灯後に繰り返す。環も経路の順序で点灯させる。操作開始時は案内を停止し、操作や判定を妨げない。押すボタンは黄色1秒・通常色1秒の明確な点滅にする。ドラッグ先のシアン色は維持する。動きを減らす設定では経路全体を静止した黄色で示し、開始マスの枠を強調する。この追補を、以下のライム色・ゆっくりした発光・開始印の記述より優先する。

## 1. 目的と変更範囲

スマホで初めて操作する学習者が「今どこに触るか」「何が成功したか」をすぐ理解でき、楽しく操作を続けられるようにする。第6課題でデッキから盤面へドラッグする置き方を覚える。

ユーザー指摘:

- 現在の淡い緑や暗い点線は目立たず、「光っている」という説明に合っていない。蛍光色やゆっくりした点滅など、はっきり目立つ案内にする。
- メッセージも既存の学習アプリ等を参考に、楽しさが伝わる出し方にする。
- テトラクロロヘキサンからジクロロジヨードヘキサンへの置換を、パネルのドラッグによる設置として案内する。

本書は初版仕様と `2026-10-21-tutorial-mobile-feedback-revision.md` を引き継ぎ、強調表示、成功メッセージ、第6課題の操作と判定を更新する。全11課題の名称・構造・論理座標、第4課題の交差描画練習、スマホ一画面表示、本体から流用した効果音は維持する。

本体統合・アルカンコンペへの変更は対象外。実装・公開は次の明示的な依頼に従う。

## 2. 参考にするデザインの考え方

以下は前回の検討時（2026-10-21）に確認した公式の設計解説。特定の演出がすべての利用者に好評という主張や、このアプリでの効果を実証した資料ではない。明快さと楽しさを両立するための参考にする。

- [Duolingoの視覚表現](https://blog.duolingo.com/shape-language-duolingos-art-style/): 鮮やかな色、弾む動き、少ない要素で明確に伝える設計。
- [Khan Academy Kidsの案内と反応](https://blog.khanacademy.org/supporting-english-language-acquisition-with-khan-academy-kids/): 成功時の動き・音・褒め言葉と、段階的な操作案内。
- [W3Cの点滅に関する指針](https://www.w3.org/WAI/WCAG21/Understanding/three-flashes.html): 急速な点滅を避ける。

キャラクター、ランキング、報酬通貨、音声読み上げなどの新機能は追加しない。今回の案内と操作への反応に適用する。

## 3. 目立つ強調表示

### 色と見た目

初期の実装値を以下とする。最終的な色味・光の強さは既存のクリーム色背景とスマホ実表示で確認し、役割を変えずに調整してよい。

| 対象 | 表現 |
| --- | --- |
| 次に押すボタン・デッキのパネル・なぞり開始マス | 蛍光ライム: 背景 `#EEFF70`、明るい枠 `#B8F500`、外側の発光。白背景でも境界が分かる細い濃色の輪郭を併用する。 |
| なぞり経路 | 通過マスを明るく塗り、経路と開始印を明示。開始マスを最も強く発光させる。 |
| ドラッグの置き先 | 蛍光シアン: 枠 `#00DDF2`、背景 `#D9FCFF`。`ここへ` の目印を添える。 |
| ドラッグ中に正しい置き先へ重なった状態 | シアンの枠と発光を一段強くし、`離す` の目印と案内文を表示する。 |
| 成功した場所 | 成功対象から星が弾け、視覚表現だけが短く弾む。 |

- 原子種の色、元素記号、結合線、薄い完成見本の読みやすさを保つ。原子のSVG自体を蛍光色に塗り替えない。
- 暗い点線だけの強調は廃止する。明るい面・実線枠・発光を組み合わせる。
- 強調のために実際のボタンやセルの寸法・位置・当たり判定を変えない。発光や弾みは重ねる表示層で表現する。
- 他のパネルや盤面全体を暗幕で覆わない。現在の操作に関係する対象だけを目立たせる。
- 色だけに依存せず、開始印・置き先の短い目印・案内文を併用する。目印は元素記号や結合線を隠さない位置へ置く。

### ゆっくりした発光

- 約1.8秒周期で、発光の強さと広がりを滑らかに往復させる。明滅は対象の背景・枠に限定する。
- 弱い側でも蛍光色と輪郭を残し、完全に消したり暗い通常表示に戻したりしない。
- 明滅させる中心は「次に触る対象」。なぞり経路は開始マスが脈打ち、残りは明るい静止表示にする。
- 第6課題のドラッグ開始前はIパネルを脈打たせ、置き先は静止したシアン枠にする。つかんだ後はデッキの明滅を止め、置き先を強調する。
- マスへの出入りや画面の再描画ごとにアニメーションを先頭から再起動しない。
- 非表示の課題やページ非表示中ではアニメーションを停止する。
- `prefers-reduced-motion: reduce` では明滅・弾みを停止し、同じ蛍光色と目印の静止表示を残す。音のオン／オフは従来どおり独立させる。

## 4. 成功メッセージと演出

### 出す場所と時間

- 画面下端に一瞬表示する方式を廃止し、盤面直上のガイド領域にまとめる。
- ガイド領域には「短い成功メッセージ1行」と「次の操作指示・原則2行」を別々に表示する。
- 標準文字サイズでは成功メッセージ用に約20〜22pxを確保し、空欄の時も盤面が動かないようにする。大きな余白や別カードは増やさない。
- 小手順成功の褒め言葉は約1.5秒表示する。次の操作指示はすぐに更新し、成功表示を待たずに操作できる。
- 新しい成功が続いた場合は最新の内容へ更新し、古いメッセージを順番待ちで蓄積しない。
- 化合物の完成時は明確な `完成！` を表示し、本人が次へ進むまで完了状態が分かるようにする。紙吹雪などの動きは約1.2〜1.5秒で終える。
- 最後は全11課題の完了を示し、既存の `練習へ`・`最初から` を利用できる状態を保つ。
- 文字拡大時は領域を自然に伸ばし、名称・盤面と重ねたり文章を切ったりしない。

### メッセージの内容

単に「すごい！」と繰り返さず、何ができたかを短く伝える。例:

| 操作 | 褒め言葉 |
| --- | --- |
| 炭素鎖をつなぐ | いいね！ つながった！ |
| 交差描画 | 一筆で枝ができた！ |
| 長押し削除 | つかんで消せた！ |
| 第6課題の1箇所目 | ドラッグで置けた！ あと1つ！ |
| 第6課題の2箇所目・課題完了 | 2つとも置けた！ 完成！ |
| OHへの置換 | OHに置き換えられた！ |

- 成功したセル付近から星が弾ける。盤面中央に毎回同じ演出を出す方式から、操作と結び付いた反応へ変更する。
- 化合物完成時は盤面全体の紙吹雪と完成表示を組み合わせる。通常成功より明確に大きい演出とする。
- 既存の本体由来の操作音・成功音・正解音を使い、音色・音量・音程は変更しない。一操作で小手順と課題が完了した場合は上位の成功演出・正解音を一度だけ出す。
- 指を離して操作が確定してから成功を表示する。ドラッグ途中・キャンセル・Undo・単なる再描画では成功扱いにしない。
- 成功表示も操作指示も読み上げ可能にする。短時間の細かなポインター移動をライブ通知で連続読み上げしない。
- 誤操作は「ここはClのままにしよう」「『戻す』で直そう」など、次にできる行動を示す。派手な失敗演出は追加しない。

## 5. 第6課題をドラッグ練習にする

### 対象と完成条件

- 開始構造: `2,2,5,5-テトラクロロヘキサン`。
- 完成名: `2,2-ジクロロ-5,5-ジヨードヘキサン`。
- 1始まりの論理座標 `(2,5)` と `(4,5)` にあるClをIに置換する。左側の2個のClは残す。
- 全体の課題番号は `6 / 11`。小進捗は `ドラッグ：0 / 2` とし、実際にIになった個数と混同しない。
- 2箇所それぞれについてデッキのIパネルから正しい位置へドラッグして離した証拠と、従来の位置・原子種・結合・命名一致の両方で完成判定する。
- 上下どちらから置いても認める。通常の案内は上から始め、済んだ対象を再要求しない。

### 案内の流れ

| 状態 | 強調・メッセージ |
| --- | --- |
| 操作前 | デッキのIをライム色で脈打たせ、次の置き先をシアン枠＋`ここへ` で示す。`Iパネルを押したまま、青く光るClへ運ぼう。` |
| Iをつかんで移動中 | 移動中のIを浮かせて表示。置き先の強調を主役にする。`そのまま青い枠まで運ぼう。` |
| 正しい対象に重なった時 | 枠を強く発光させ、`ここで指を離そう！` と表示する。まだ達成にはしない。 |
| 正しく離した時 | Iを確定配置し、その対象のドラッグを達成。星・本体の音・褒め言葉を出し、残る位置を案内する。 |
| 2箇所達成かつ構造一致 | 課題完成。本人が `次へ` を押して第7課題へ進む。 |

- デッキからのドラッグは、従来の移動開始しきい値を利用する。長押しは要求しない。「長押しして」と誤って案内しない。
- 他方の正しい未達成の位置へ運んだ場合も、重なりの反応を出して受け入れる。
- 光る枠だけでなく、短い目印と文章で出発点・置き先・離すタイミングが分かるようにする。

### タップや誤操作からの復帰

- Iを選んでタップ配置した場合は構造の変更を保持するが、ドラッグ達成にはしない。
- その場合は `今度はIパネルを、同じ場所へドラッグしてみよう。` と案内し、すでにIの場所を置き先として強調する。`Clへ` という実態に合わない文言を残さない。
- 同じIの上へデッキから正しくドラッグすれば達成する。盤面差分がなくても操作証拠を記録し、履歴・進捗・成功演出を更新する。
- Iパネルをタップしただけなら、選択状態を理由にタップ配置を促さず、押したまま運ぶ案内を続ける。
- 盤面上のIを移動した操作、他の元素のドラッグ、別の位置への配置は第6課題のドラッグ達成に数えない。
- デッキから盤面外へ離した場合は盤面を変えず、同じ小手順に留まる。
- 誤ったマスへの配置は既存の通常操作として扱い、自動で正しい位置へ吸着させない。進捗は増やさず、Undo等で修正を案内する。
- キーボードの通常配置は継続して利用可能にするが、ドラッグをしていない操作をドラッグ達成と偽って数えない。新しいキーボード用ドラッグモードの追加は本改訂の範囲外。

## 6. 状態・履歴・実装上の条件

- 確定操作の情報に「デッキ由来のドラッグ」「元素I」「リリースした対象マス」が識別できる情報を渡す。最終構造や `place` という種類だけで、タップとドラッグを推測しない。
- 第6課題の達成状態は2箇所分のフラグとして管理し、盤面・既存の進行状態とともにUndo履歴へ入れる。盤面が変わらない成功ドラッグも1操作として取り消せるようにする。
- Undoで成功したドラッグを取り消すと、その位置の達成と小進捗を戻し、必要なら `次へ` を無効にする。
- `やり直す` は第6課題開始時のテトラクロロ構造とドラッグ未達成状態へ戻す。
- クリアとUndo、段階の切替、リロードの規則は既存どおり。前の課題の達成フラグを流用しない。
- `pointercancel`・blur・ページ非表示時はドラッグ開始前へ復元し、達成を追加しない。ゴースト、置き先の重なり表示、古い成功メッセージを整理する。
- 第4課題の一筆描画・長押し削除・再描画の達成判定と履歴を壊さない。
- 主な変更対象は `tutorial.css`、`tutorial.html`、`tutorial.js`、`tutorial-steps.js` と関連テスト。既存の音声生成処理・命名処理は変更不要。
- 教材の操作要件は第6課題のデータで識別できるようにする。汎用チュートリアル基盤や新しいライブラリは導入しない。

## 7. 検証・受け入れ条件

### 強調とメッセージ

- 実際の表示で、通常セルと案内対象の違いが一目で分かる。蛍光色・実線枠・発光が弱い側の状態でも見える。
- 静止画だけでなく、1.8秒周期の途中と前後を観察して発光の連続性を確認する。単にCSSのクラスが付いていることを検証の代わりにしない。
- なぞり開始点、クリアボタン、選ぶパネル、ドラッグ元と置き先をそれぞれ確認する。何箇所も無関係に点滅していない。
- 原子記号と結合線が読み取れ、枠・目印・星で構造が継続的に隠れない。
- 成功した場所と反応の位置が対応する。褒め言葉はガイド領域で約1.5秒読め、次の指示も同時に分かる。
- 成功表示・文言の変更中に盤面とデッキが動かない。演出中も次の操作ができる。
- 320×568、390×664、430×740 CSS pxで全11課題の通常・成功・クリア待ち・ドラッグ中の表示が一画面に収まる。768/1280px幅も確認する。
- ボタン間の隙間を維持する。主要操作のタップ領域を削って収めない。文字拡大時は切らずに伸長・スクロールできる。
- 動きを減らす設定でも静止した強調と成功表示が分かる。消音時にも操作と成功を理解できる。

### 第6課題と回帰

- 上→下、下→上のどちらの順でも2回のデッキドラッグで完了できる。
- 2箇所ともタップでIへ置換しても完了しない。その後、同じIへドラッグすると進捗が増えて完了できる。
- タップだけ、重ねただけ、間違った元素、盤面上のIの移動、誤った位置への配置、枠外リリース、キャンセルではドラッグ達成にならない。
- 正しい位置へ重なった後に外して離した場合も達成しない。最終リリース位置で判断する。
- 同じ達成済みの位置へ繰り返しドラッグしても、2箇所分に数えない。
- 盤面差分のない成功ドラッグをUndoすると達成が戻る。やり直す・クリアからのUndo・段階切替でも盤面と達成が一致する。
- 第4課題を含む全11課題を実操作で通す。通常のタップ配置・長押し移動・なぞり・音声切替の回帰を確認する。
- Chromium・WebKitで検証し、タッチ入力のエミュレーションと実機確認を区別する。実機で未確認の項目を確認済みと報告しない。
- 実行時エラー、予期しない通信失敗、共有設定への読み書きがない。変更範囲に適したテストと `git diff --check` を通す。
- 公開が依頼された場合は、配信内容の一致と、公開ページでの第6課題のドラッグ・同じIへの置き直しを確認する。
