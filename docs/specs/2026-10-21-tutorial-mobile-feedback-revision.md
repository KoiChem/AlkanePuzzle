## 1. 目的・適用範囲

スマホで初めて操作する学習者が、盤面とデッキをスクロールで往復せず、短いガイドと成功の手応えを得ながら操作を覚えられるようにする。

ユーザー確認済みの追加練習は「上下を貫く縦のスワイプで、既存の横鎖に交差する枝を一度に描く」操作、その枝の長押し削除、同じ経路の一筆描き直し。効果音は本体にあるものをそのまま流用する。

初版仕様 `2026-10-21-arrange-guided-tutorial.md` の全11化合物・完成名称・原子配置・命名判定・独立試作という範囲を引き継ぐ。本書は次の初版条件を置き換える。

- 常時5行表示 → 練習群ごとの必要行だけ表示。
- 大きなページ見出し・常設補足文 → 削除し、現在の操作案内へ集約。
- 第4段階は完成構造のみで通過 → 指定操作の達成と完成構造の両方が必要。
- 効果音は任意 → 本体の既存音を流用して実装する。
- 通常スマホでも縦スクロール可 → 標準文字サイズの縦持ちスマホでは全操作を一画面内に収める。

本体への入口追加、アルカンコンペへの組み込み、命名ルールの変更は今回の改訂範囲に含めない。公開は次の実装依頼に含まれる場合に行う。

## 2. 画面構成

上から次の順にする。

1. コンパクトな上部行: 段階番号（例 `4 / 11`）、音の切替、`練習へ`。
2. 完成目標の化合物名。
3. 現在の短い操作指示と小手順の進捗。
4. 盤面。
5. デッキ（上段: 戻す＋F・Cl・Br・I・OH、下段: 炭素5種）。
6. `クリア`・`やり直す`・`次へ`。最終完成時は初版どおり `最初から` を表示。

### 省スペース化

- 表示上の「アルカンパズル」「操作チュートリアル」の見出しを削除する。HTMLのページタイトル・必要な読み上げ用名称は維持する。
- 化合物名の固定高さ116px/96pxを廃止し、実際の折り返しに必要な高さにする。名称の省略や横スクロールはしない。
- 操作指示は原則1〜2行。狭幅・文字拡大時は折り返しを許し、切り捨てない。
- 同一課題の操作中は指示・成功文の切替で盤面が動かないよう、必要最小限の案内領域を確保する。課題切替時の高さ変更は許容する。
- デッキ下の常設補足文と画面最下部の操作一覧を削除する。環が6炭素である説明など、必要な内容は該当小手順で短く案内する。
- `この段階をやり直す` を `やり直す` に変更し、案内文も統一する。
- 余白を先に削減し、ボタン間隔や押しやすさを犠牲にしない。隣接ボタンは縦横・折返しとも明確に離す。主要操作は44px以上のタップ領域を確保する。
- 成功演出や削除先表示のための恒常的な空白領域は設けない。

### 盤面の行数と座標

判定用の論理座標は初版の5行×7列・1始まりの座標を保持し、表示する行だけを変える。名前・原子種・結合の判定は非表示行も含む盤面全体に対して行う。

| 課題 | 通常表示する論理行 | 表示行数 |
| --- | --- | --- |
| 1 プロパン | 3 | 1 |
| 2 3-エチルペンタン | 1〜3 | 3 |
| 3〜7 ヘキサンからジオール | 2〜4 | 3 |
| 8〜11 環とその置換 | 1〜4 | 4 |

第2・3・8課題のクリア待ちは、前の構造を欠けずに表示するため「前課題の表示行と次課題の表示行の和集合」を使う。特に第3課題のクリア待ちは1〜4行の4行表示にし、本人がクリアした後に2〜4行へ切り替える。Undoでクリア待ちへ戻した場合も表示範囲を復元する。

構造を引き継ぐ第3〜7課題、第8〜11課題の途中では行数を変えない。小手順や削除時に自動で空行を畳まない。非表示セルは描画・フォーカス・当たり判定の対象から外し、ルート表示とポインター座標を可視盤面に合わせる。列は7列を維持する。

### 高さの基準

- ブラウザの上部・下部バーを除いた実際の表示領域に収める。`100dvh` 等を使い、ブラウザのバーやセーフエリアに主要操作を隠さない。
- 標準文字サイズで少なくとも320×568、390×664、430×740 CSS pxのビューポートで、全11課題・クリア待ち・長い名称・成功状態の盤面と主要操作が縦横スクロールなしで見えることを確認する。
- 横持ちの低い画面やユーザーによる文字拡大時は、内容を切らずスクロールで到達できるようにする。`overflow:hidden` で隠して合格扱いにしない。

## 3. 第4課題に追加する操作練習

課題名は `2,2,5,5-テトラメチルヘキサン`、大きな番号は `4 / 11` のまま。初版の枝数だけの進捗を、下記6小手順の進捗に置き換える。

| 小手順 | 操作と達成条件 | ガイド文の例 |
| --- | --- | --- |
| 1 | 2位の上枝 `(3,2)–(2,2)` を作る | 光る炭素から上へ、枝を1本作ろう。 |
| 2 | 2位の下枝 `(3,2)–(4,2)` を作る | 今度は下へ、枝を1本作ろう。 |
| 3 | `(2,5)→(3,5)→(4,5)` を一回のスワイプで描く | 上から下まで一筆でなぞろう。下から上でもOK。 |
| 4 | 上枝先 `(2,5)` を長押しし、盤面外で指を離して削除 | 上の枝先を長押しして、枠の外へ運んで離そう。 |
| 5 | 下枝先 `(4,5)` を同じ方法で削除 | 下の枝先も、長押しして枠の外へ運ぼう。 |
| 6 | 同じ縦3マスを一回のスワイプで再描画し、完成構造に戻す | もう一度、上下を一筆でつなごう！ |

### 操作判定の詳細

- 小手順1・2は逆順で作っても認める。先に済んだ正しい枝を再要求しない。
- 小手順3・6は上→下、下→上のどちらも認める。一本のポインター操作で3マスを順に通り、中央で主鎖の左右の結合を維持し、上下の枝を作ったことを確認する。
- 分割して上下の枝を作っただけでは小手順3・6の達成にしない。構造を保持したまま「上下を一度につなぐように、もう一度なぞろう」と案内し、一筆で重ね描きすれば達成可能にする。
- 小手順3で一度完成構造になっても課題全体は未完了。ここでは小手順成功のみを祝い、削除練習へ進む。
- 小手順4・5は上・下どちらから削除しても認める。各枝先について、長押し成立→移動→盤面外でリリースの一連の操作が必要。中央の主鎖炭素は削除しない。
- 3タップ削除やクリアでは長押し削除の達成にしない。誤った方法で対象が消えた場合は「『戻す』で枝を戻して、長押しで消してみよう」と案内し、詰まらず復帰できるようにする。
- 長押し中にだけ削除先の案内を重ね表示する。盤面外へ移動した時点で「離すと削除」と表示する。盤面や操作ボタンの位置は動かさず、ドラッグを奪わない。
- 主鎖・2位の枝の誤編集は通常どおり修正可能。途中状態を勝手に完成形へ置換しない。削除途中の未完成構造に最終見本との不一致エラーを出さず、現在の小手順を優先して案内する。
- 削除で残る結合表示の扱いは本体の既存規則に従う。小手順6の描画後に整合した完成構造へ戻り、命名に成功することを確認する。

### 完成・Undo・キャンセル

- 第4課題の完了条件は、6小手順の達成と、初版の位置・原子種・結合・命名一致の両方。
- 操作達成は確定した操作の種類・経路・移動元・リリース先と操作前後の盤面から判定する。最終盤面だけから「長押しした」「一筆だった」と推測しない。
- すでに同じ完成形の上を一筆でなぞった場合も、小手順の条件を満たせば進行状態の変更として扱う。盤面差分なしを理由に通知や履歴を捨てない。
- Undo履歴には盤面、クリア待ち、復帰案内に加え、操作達成状態も含める。削除や再描画を取り消したら、その直前の小手順に戻る。
- `やり直す` はヘキサンの開始盤面と未達成の小手順に戻す。次の課題へ進むと履歴を区切る。
- `pointercancel`・blurでは操作開始前へ戻し、進行・成功音・成功演出を確定しない。
- 第4課題の指定操作以外は、初版どおり分割描画や異なる正しい操作順を認める。

## 4. 効果音 — 本体の既存音をそのまま流用

本体 `index.html` に存在する音色、音程、長さ、音量、音の並びを変更せず移植する。似た音を新しく作り直したり、外部音源を追加したりしない。新しいファンファーレも作らず、本体の正解音を使う。

| 用途 | 本体の参照関数 |
| --- | --- |
| 配置・移動・長押し成立 | `playPlaceSound` / `playMoveSound` / `playPanelPickupSound` |
| 回転・逆回転・削除 | `playRotateCWSound` / `playRotateCCWSound` / `playDeleteSound` |
| パレット・Undo・クリア・UI | `playPaletteSound` / `playUndoSound` / `playClearSound` / `playUiClickSound` |
| なぞり中・引き返し・環を閉じる | 本体のtrace系効果音関数と、その発音条件 |
| 小手順の成功 | `playValidSound` |
| 化合物の課題完了 | `playCorrectSound()` |
| 全11課題完了 | `playCorrectSound({ sparkle: true })` |

- なぞり音の発音間隔・経路の巻き戻し・連続音の制御も本体に合わせる。`pointermove` の回数だけ無制限に発音させない。
- 音声の初回解禁、iOS復帰、音声キューの上限・破棄、消音処理など、必要な音声基盤も一緒に流用する。本体の画面状態への依存だけをチュートリアルの状態へ接続する。
- 初期状態はオン。上部にSVGの音切替ボタンを置き、状態と読み上げ名を更新する。音の設定はページ内メモリのみで保持し、本体のlocalStorageを読み書きしない。
- 無音にすると予約済み音を破棄し、再びオンにしても古い音がまとめて鳴らない。
- 同じ操作で小手順と課題全体が完成する場合は、成功音を重ねず、上位の課題完了音だけを鳴らす。通常の操作音は本体どおり扱う。
- ブラウザが音を許可しない場合も操作と進行は継続する。実際のユーザー操作で解禁・復帰を試みる。自動テスト上の呼出成功と実機で聞こえたことを区別して報告する。

移植先は必要なら `tutorial-audio.js` とし、出典コミット・関数名を記録する。本体を全面的に共通モジュール化する必要はない。

## 5. 成功を褒める演出

全11課題に適用する。単なるタップ回数ではなく、ガイドに沿った意味のある操作が確定した時に褒める。

| 成功の単位 | 演出 |
| --- | --- |
| 枝追加・置換・指定削除・一筆描画などの小手順 | 成功対象から星が弾ける、短い褒め言葉、既存の成功音。約0.6〜0.9秒。 |
| 1化合物と指定操作の完了 | より広い紙吹雪と「完成！」、既存の正解音。約1.2秒。 |
| 全11課題の完了 | 一段大きな紙吹雪と達成メッセージ、sparkle付き既存正解音。約1.5秒。 |

褒め言葉の例:

- 「横のつながりを残して、枝を作れた！」
- 「長押しでつかんで消せた！」
- 「一筆で描き直せた！」
- 「OHに置き換えられた！」

演出は少し派手にするが、全画面の強い点滅や画面揺れは使わない。操作を遮らない重ね表示（ポインターを透過）にし、演出待ちを強制しない。次のガイドはすぐ分かる状態を保ち、褒め言葉で次の指示を覆わない。

- 確定前の通過状態では褒めない。再描画やresizeで同じ達成を繰り返し発火させない。
- 一操作で複数の通常小手順を達成した場合は、まとめて一度祝う。
- Undo・クリア・やり直す自体を成功扱いにしない。Undo後に必要な操作を改めて成功させた場合は再び褒めてよい。
- 誤操作に派手な失敗音や罰の演出を追加しない。修正対象を短く示す。
- 音・色だけに依存せず成功文を表示し、読み上げにも通知する。`prefers-reduced-motion` では粒子移動や拡大を抑え、静的な成功表示を残す。
- 連続成功時に古い粒子・音・通知を大量に溜めない。ページ非表示・課題遷移・やり直す時は古い演出を整理する。

## 6. 実装対象と受け入れ条件

主な対象は `tutorial.html`、`tutorial.css`、`tutorial.js`、`tutorial-steps.js`。必要な音声移植ファイルと進行・操作のテストを追加する。命名処理や本体の通常動作を変更しない。汎用イベント基盤は不要で、確定操作に種類と必要な経路情報を付ければよい。

### 操作・進行

- 全11課題を実際のポインター操作で通し、従来の完成名称が得られる。
- 第4課題で上→下／下→上の一筆交差描画が成功する。横鎖の左右の結合が保たれる。
- 分割描画だけでは進行せず、同じ構造の上を一筆でなぞり直すと進行する。
- 上下の長押し削除がどちらの順でも達成できる。3タップ削除では達成せず、Undoから復帰できる。
- 最初のテトラメチルヘキサン完成時は「次へ」が無効で、削除・再描画後に有効になる。
- 各小手順でUndo・やり直す・誤クリア・pointercancel・blurを確認し、盤面と達成状態が一致する。
- 非表示行に余分な原子があれば完成しない。クリア待ち・Undoで前構造が欠けない。

### 表示・音・演出

- 指定したスマホ3サイズで全課題の通常状態・クリア待ち・成功表示が一画面に収まる。768/1280px幅も確認する。
- 最長名・エラー文・成功文でも盤面が操作途中に移動せず、ボタンは接触しない。
- 長押し削除先が見え、盤面の上下どちらからも枠外でリリースできる。表示を詰めても削除操作がブラウザUIに隠れない。
- 本体と同じ発音パラメータ・対応する操作タイミングであることを確認する。初回操作、消音・再有効化、連続描画、画面復帰も確認する。
- 成功演出が確定時だけ発火し、通常の再描画で再発火しない。無音・動きを減らす設定でも達成が分かる。
- ChromiumとWebKitで操作を検証する。実機iPhone/iPadの音声出力・ブラウザバー込みの収まり・長押しの感触は別の実機確認として報告する。
- コンソールエラーと予期しない通信失敗がない。表示行数変更・resize・一時的な盤面サイズ0でもガイドSVGに不正座標を生成しない。
- `git diff --check` と変更範囲に適した回帰テストを通す。ユーザーの既存変更をコミットに混ぜない。

公開が依頼された場合は、配信された変更ファイルとデプロイ成功を確認し、公開ページでも交差描画→長押し削除→再描画を通して検証する。本体統合は別途の依頼に従う。
